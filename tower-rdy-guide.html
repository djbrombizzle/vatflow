RDY & Ready Time

How destination and FCA metering decide crossing times, why one airplane gets an earlier slot than another, and how to issue Ready Time or RDY without guessing.

Two release systems

Airport TMU meters arrivals into a destination (AAR / trail / MIT). You issue CFR time and optional Ready Time on Departures / My Dashboard.

FCA meters aircraft across a line. You issue RDY (with optional HHMMz floor) on the Release Board. When a row shows FCA PRGM, FCA is authoritative — do not treat Airport TMU capacity slots as the release source for that aircraft.

Before you start

Sign in with VATSIM. Airport TMU CFR issue needs controller access for that ARTCC. Release Board RDY needs sign-in while you are online on a controller position. Ready Time (HHMMz + Set) can be entered without a control password on Airport TMU rows.

Why VATFLOW exists for tower

Arrival fields and FCA lines have limited capacity. If everyone rolls when ready, airborne traffic absorbs the delay. VATFLOW moves that delay onto the ground as a wheels-up time so you release in an order that protects the stream ahead.

  • The app watches live VATSIM traffic and the active programs (destination AAR or FCA rate/MIT).
  • It proposes when each departure should roll so it fits the schedule at the dest or crossing.
  • You lock that proposal with CFR time / RDY (and optionally a Ready Time floor from the pilot).

Key terms

Same ideas, slightly different labels depending on the tool.

CFR / EDCT / wheels-up
The assigned takeoff time. Airport TMU calls the button CFR time. FCA calls it RDY / RLSD.
STA
Scheduled time of arrival at the destination (Airport TMU). Driven by ETA plus rate and gate spacing.
Crossing / CTA
Scheduled time across the FCA line. Wheels-up is backed out from that crossing using estimated transit time.
Ready Time
Pilot-estimated earliest wheels-up (HHMMz). Acts as a floor — the app never issues before it; spacing may still push later.
AAR / Rate
Airport Arrival Rate (arrivals per hour) or FCA crossings per hour.
MIT / trail
Miles or minutes in trail between successive aircraft (overall or per arrival gate).
Gate
Arrival fix or STAR from the filed route — used for same-route spacing at the destination.
FCA line
A metering line drawn in FCA Builder. Aircraft join only when their filed route crosses it.

How Airport TMU times work

Destination metering builds an arrival schedule, then backs out wheels-up for ground departures.

What is fixed vs proposed

  • Airborne arrivals keep times based on ETA. Ground traffic never delays an airborne aircraft. Spacing uses the AAR interval plus same-gate trail/MIT when applicable.
  • Already-issued CFRs keep their locked wheels-up. Their STA is wheels-up + flight time, and that slot is reserved.
  • Unissued ground / proposed flights slot into remaining capacity. Proposed wheels-up = STA − flight time. A delay (and a CFR need) appears when that wheels-up is after “now.”

Issuance priority

When you press CFR time, VATFLOW assigns the earliest open wheels-up constrained by:

  • Airborne arrival slots at the destination
  • Other already-issued CFRs into that field
  • A 2-minute release gap against other issued CFRs on the same dep → dest route
Unissued peers do not block you

Other BOS→JFK departures sitting unissued do not hold the first slot. Whoever you issue first gets the earliest open time. That is why issuance order matters — and why swap exists when taxi order and issuance order diverge.

Why airplane A is earlier than B

  • You issued A first (A claimed the open slot).
  • A has a shorter enroute / earlier natural ETA into capacity.
  • A has less same-gate conflict than B.
  • A has no Ready Time floor (or an earlier floor) than B.
  • Someone cancelled a CFR and A was pulled earlier into the freed slot (green “pulled” flash).

How FCA crossing times work

Line metering is about when aircraft cross the FCA — not destination AAR. Tower’s job is freezing a ground release when the pilot is actually ready.

Who is included

  • Only aircraft whose filed route crosses the enabled FCA line (filters for dest/origin/fix/FL/scope still apply).
  • Crossing ETAs use a climb/cruise model and winds — not taxi groundspeed. Filed departure time is ignored for the release.

Air vs ground

  • Airborne crossings are fixed by ETA. The tool does not delay them to invent a clean timeline; conflicts between air are flagged for the controller.
  • Ground strips stay advisory until you press RDY. Unready aircraft hold no slot — a ready aircraft can claim what an unready one was only projected into.
  • After RDY, wheels-up = frozen crossing time − transit. Frozen releases move later only if needed (air encroachment or a missed CFR window) — not earlier for convenience.

Why airplane A crosses sooner than B

  • A is closer / has an earlier ETA to the line.
  • You pressed RDY on A first, so A froze the open gap.
  • Manual sequence order puts A ahead of B (drag reorder when you have edit control).
  • Rate or MIT spacing ahead of B pushes B later.
  • A’s Ready Time floor is earlier (or absent) compared with B.

How to issue

Ready Time is the pilot’s “I can’t go before…” floor. CFR time / RDY is you locking the slot.

  1. 1

    Ask for ready

    When the pilot calls ready (or quotes an estimated wheels-up), decide whether they can go at the next open slot or need a later floor.

    Pilot · “Ready in 10” / “Ready now”
  2. 2

    Optional Ready Time floor

    Enter HHMMz in the Ready Time field and press Set (Airport TMU) or SET then RDY (Release Board). The release is never before that time; spacing may still push later.

    Column · READY TIME · HHMMz
  3. 3

    Lock the release

    Airport TMU: press CFR time (or Set after Ready Time — assigns earliest valid at/after the floor).
    FCA: press RDY. One-click RDY without a time uses the ready-now buffer.

    Departures · My Dashboard · Release Board
  4. 4

    Read the badge

    Released — no delay needed; release at will.
    Release now — wheels-up has arrived.
    Countdown / green RLSD — issued time is locked. Tell the pilot that wheels-up.

    CFR cell · strip badge
  5. 5

    Fix order mistakes

    Use Swap with… on Airport TMU when two same-route CFRs need to exchange times (taxi order ≠ issuance order). Cancel with × / RLSD ✕ to free a slot — Airport TMU may pull remaining issued times earlier.

    Issued row · swap · cancel

Airport TMU path

  1. Open Airport TMU → Departures or My Dashboard
  2. Confirm the dest has a TMU program (or note FCA PRGM)
  3. Optional: Ready Time HHMMz → Set
  4. Press CFR time / follow FCA RDY if FCA PRGM is set
  5. Swap or cancel if taxi order changes

Release Board path

  1. Open Release Board
  2. Select ARTCC / airport / PCT filter → Load
  3. Sign in while online on a controller position
  4. Optional HHMMz → SET, then RDY (or RDY now)
  5. RLSD = issued · press again to cancel

Best practices

Small habits that keep the sequence honest for everyone sharing the program.

  • Don’t RDY / CFR spam before the pilot is ready. Freezing early steals a slot an actually-ready aircraft could use.
  • Use Ready Time when the pilot quotes a later taxi or wheels-up. That protects the schedule from an impossible “now” release.
  • Issue in taxiway / runway order when you can. If you issued out of order, swap (Airport TMU) instead of cancelling the whole stream.
  • One position owns a stream when possible. Multiple people issuing the same dep→dest or FCA without coordination creates thrash.
  • Stay on Live sync / the shared room so your issues and cancels show for the next controller.
  • Respect special rows: VFR and “NO PROGRAM — RELEASE AT WILL” need no CFR. Ground stops override — hold until the GS ends.
  • When FCA PRGM is set, use Release Board / FCA RDY. Airport capacity slots are not the source of truth for that aircraft.
  • After a cancel, watch for pulled-up times (earlier green flash) and re-brief the pilot if their wheels-up moved.
